# 科研应用与验证登记机制实施记录

日期：2026-10-08。范围：当前同步目录的根目录文档；不涉及运行时修订或新科学测试。

## 背景与动机

项目已进入收集真实科研使用与失败证据的阶段。需要持续记录研究问题、研究领域、论文及能力证据，避免把“用过 Skill”“论文发表”和“验证 Skill”混为一谈。此次建设由用户明确指定，沿用现有 Markdown、双语 README 和 issue / pull request 贡献方式。

先读取 `PROJECT_STATE.md` 和 `AGENTS.md`，再检查 README、贡献指南、`SKILL.md`、两份解释性 reference、已有验证记录及相关脚本。根目录原先没有应用登记总表，也没有 `cases/`；`revisions/v0.1-alpha.2/public-release/` 中有案例簿，但它与根目录的 README、贡献指南存在既有差异。本次不同步或修改该发布副本，不复制历史案例目录。

## 为什么采用独立登记

科研使用记录属于应用与证据管理，不是运行时推理方法。本次没有发现或测试新的 Skill 行为缺陷，也没有修改核心方法的授权。因此新增独立的 [RESEARCH_APPLICATIONS.md](../RESEARCH_APPLICATIONS.md)，保留 [SKILL.md](../SKILL.md) 的规范性地位，不修改版本、Core Rules 或 OAC。

## 科学与开源治理目标

- 分开登记实际探索的研究问题、作者明确确认使用 Skill 的论文，以及可复现的能力测试、比较或独立审查。
- 背景文献不冒充 Skill-assisted publication；实际使用、论文发表和应用完成均不自动意味着能力验证。
- 署名需经确认并允许披露；论文需记录作者确认来源与日期；验证证据保留所测版本、环境、方案、结果与限制。
- 允许明确登记缺失证据、失败或混合结果，不要求参与者先建立完整 benchmark。受限材料不表述为公众可复现证据。

## 限制与失败条件

目前只有计划占位，尚无已登记的实际使用或经作者确认的论文。HL-3 具体研究问题、使用记录与披露许可仍待提供；不得根据名称或历史 benchmark 推断实际应用已经完成。

若只有背景引用、没有作者确认，论文不能进入“使用 Skill 的论文”字段。若无法获取测试材料、准确版本或审查依据，应明确证据限制，不宣称可复现验证或跨领域有效性。发生确认撤回、链接失效或证据与版本不符时，应修正相关条目并保留必要来源说明。

同步目录缺失 Git 元数据，且根目录与发布副本不同步。本次文件修改可供审阅，但不代表已进入公开仓库；之后应在有 Git 元数据的检出中逐项合并，检查现有修改后再考虑提交。本次没有发布。
