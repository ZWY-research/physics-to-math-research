# v0.2.5：按用途交付科研成果

本轮按已审查、明确授权的设计改善交付行为，不基于虚构的模型失败修复，不增加科研 Core。阅读、研究、仅审查及成果表达的目的不同，默认完整科研流程会偏离用户任务；因此只增加短小运行指引，详细说明按需放入 references。

完整交付可用通俗版让跨学科读者理解问题与边界，用专业版让研究者复核定义、推导和证据。两层结论与证据必须一致，不强制两篇长文或两个文件。Nature 类默认仅用于未指定风格的明确学术写作请求，指清晰、简练、证据导向的表达；明确风格覆盖默认，具体投稿格式仍依官方指南，不扩展为完整投稿系统。

现有获授权工具执行核查与要求用户安装软件是不同事项。阅读任务不自动提供安装教程，本地部署需求只给最小相关方案，安装须明确授权。成果回执只说明实际工作、支持状态、实际工具及真实产物。

修改 SKILL.md、两份 README、CHANGELOG.md 和 docs/index.html 的版本；新增 references/research-deliverables.md、examples/research-delivery-cooling.md、examples/integrated-density.md、tests/research-delivery-near-pairs.md 及本记录。原密度积分演示完整保留，首页用条件性冷却模型表达通用使命。Core/OAC、原论文与评估证据、打包脚本保持不变。

验收：逐字节核对冻结内容与修改范围；检查 YAML、轻量格式、双语语义、相对链接、数学定界符及 Observatory 一致性；发布后检查 ZIP 内容与哈希。仅静态验收，不声称真实 GitHub 数学渲染预览。近邻回归状态为 Specified — Not yet run，不运行模型，不宣称增量科研能力。发布提交和产物哈希另记于私有 PROJECT_STATE.md。

失效条件包括用途误判、默认写作覆盖明确要求、双层结论漂移、安装越权或虚构工具／文件。本轮静态验收不能排除这些行为风险。

下一逻辑节点：等待明确授权或真实使用反馈，再执行已指定近邻回归；本轮完成发布与打包后停止。
