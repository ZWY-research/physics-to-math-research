# Research Deliverables / 科研成果表达

Supporting guidance, read when relevant; [SKILL.md](../SKILL.md) is the sole runtime authority. These purposes are not a routing system or mandatory sequence.

本说明按需读取；[SKILL.md](../SKILL.md) 是唯一运行规范。用途区别不构成路由系统或强制流程。

## 1. Purpose / 用途

Reading and understanding explains existing literature and methods without forcing independent research. Research and derivation advances a supported scientific-to-mathematical question; audit-only work need not propose a model. Communication organizes results already obtained, without inventing missing findings. Explicit user requirements govern. Pure literature reviews and complete submission writing remain outside this Skill's independent core responsibilities.

文献理解解释已有论文与方法，不强制独立研究；科研数学化推进当前条件支持的科学数学问题，仅审查无需提出模型；成果表达整理已有结果，不补造缺失发现。明确用户要求优先。纯文献综述和完整投稿写作仍非本 Skill 的独立核心职责。

No fixed paragraph counts, mandatory equations, full papers or local files. A short question may need only a short answer.

不规定段落数量，不强迫方程、完整论文或本地文件。简短问题可以简短回答。

## 2. Research Explanation / 通俗解释版

For university-level interdisciplinary readers, explain the question, what was assumed, what the method achieves, the result and its limits. Define necessary terms; simplify presentation without strengthening the conclusion, hiding evidence limits or discarding load-bearing assumptions. This is not automatically Nature-style writing.

面向大学水平跨学科读者，说明问题、假设、方法用途、结果与边界，解释必要术语。可以简化表达，不能强化结论、隐去证据限制或删去关键假设。此层不自动采用 Nature 类写作。

## 3. Technical Research Account / 专业科研论证版

Include definitions and domain, relevant premises and scientific correspondence, decisive derivations or counterexamples, evidence status and enough actual reproduction information for the result. Use only the mathematical complexity the question needs. Keep the same conclusion, evidence strength and applicability as the explanation. Two accounts need not be separate long essays or files; the task and requested delivery determine form.

提供定义与适用域、相关前提及科学对应、决定性推导或反例、证据状态和复核结果所需的真实复现信息。数学复杂性应服务问题；与通俗版保持相同结论、证据强度与适用范围。两层无需成为两篇长文或两个文件，形式由任务与交付要求决定。

Existing Nature-style writing tools may help only with an explicit user need, tool availability and authorization; they are not mandatory dependencies or automatically invoked.

只有用户明确需要、工具可用且已授权时，才可衔接已有 Nature 类写作工具；它们不是强制依赖，也不自动调用。

## 4. Academic writing style / 学术写作风格

For requested research-result writing, academic paragraphs or professional academic argument without another specified style, use clear questions, prominent findings and significance, restrained terminology, mathematics supporting scientific claims, evidence-matched conclusions and concise interdisciplinary prose. This expression default is informed by [Nature Portfolio writing guidance](https://www.nature.com/nature-portfolio/for-authors/write), rather than a journal submission template.

明确请求撰写科研成果、学术段落或专业学术论证且未指定其他风格时，采用问题清晰、发现与意义突出、术语适度、数学支持科学主张、结论对应证据、面向跨学科读者的简练表达。该表达默认参考 [Nature Portfolio 写作指导](https://www.nature.com/nature-portfolio/for-authors/write)，不等于投稿模板。

Brief disclosure: “Scientific writing defaults to a clear, concise, evidence-oriented Nature-style approach; please specify Nature Communications, Nature Physics, another journal or a different writing style if preferred.”

简短告知：“科研写作默认采用 Nature 类期刊的清晰、简洁、证据导向风格；如果需要 Nature Communications、Nature Physics、其他期刊或不同的写作风格，请直接指定。”

Explicit journal, style, language or organization overrides the default. Exact submission requirements come from the target journal's current official guide, such as [Nature Communications author instructions](https://www.nature.com/ncomms/submit/how-to-submit). Do not impose this style on ordinary explanations, invent data, citations, originality or experiments, or expand into a complete submission-writing system.

明确指定的期刊、风格、语言或篇章组织覆盖默认。精确投稿要求以目标期刊当前官方指南为准，例如 [Nature Communications 作者指南](https://www.nature.com/ncomms/submit/how-to-submit)。不强加于普通解释，不虚构数据、引用、原创性或实验，不扩展为完整投稿写作系统。

## 5. Tools and a truthful receipt / 工具真实性与真实回执

Use existing authorized tools for material checks under Conditional verification. Existing-tool use does not imply local installation. Do not automatically recommend software or load installation instructions for ordinary reading. Only explicit local-computation, deployment or installation needs call for a minimal relevant plan; installing locally still requires explicit authorization. Tool output does not replace proof or empirical evidence. Record actual tool roles and execution limits; never invent execution logs or computation files. File locations must point to files actually created and present.

按条件性核查指引用已授权的现有工具核查关键结果。使用已有工具不等于本地安装。普通阅读不自动推荐软件或加载安装说明；只有明确的本地计算、部署或安装需求才给出最小相关方案，本地安装仍须明确授权。工具输出不替代证明或经验证据。如实说明工具作用与执行限制，不虚构执行记录或计算文件；文件位置必须指向实际创建且存在的文件。

Dialogue-only receipt example: “Under the stated constant-temperature and proportional-rate assumptions, the temperature difference decays exponentially. This is an analytic conditional result, with no external calculation software or empirical check; no files were created.”

纯对话回执示例：“在环境恒温及速率正比于温差的假设下，温差指数衰减。这是解析条件性结果，未调用外部计算软件，未完成经验检验，也未创建文件。”

Repository teaching-artifact receipt example: “[research-delivery-cooling.md](../examples/research-delivery-cooling.md) contains accessible and technical accounts of the same analytic model. It documents assumptions and limits; it is not empirical validation.” This is an existing source-repository artifact, not a claim that an installed Skill package includes examples. For user-requested files, report their actual names, absolute locations and purposes after creating them.

仓库教学产物回执示例：“[research-delivery-cooling.md](../examples/research-delivery-cooling.md) 提供同一解析模型的通俗版和专业版，记录假设与限制，不构成经验验证。”这是源码仓库中的现有产物，不表示安装包包含 examples。用户要求生成文件时，应创建后报告其真实名称、绝对位置和用途。
